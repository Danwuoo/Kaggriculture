# D0--D4 implementation plan

## D0: controls and seed semantics

1. Freeze pre-change generated artifacts, route/source files, opponents, and
   exact engine/config hashes.
2. Repair each incumbent's independently owned runtime with an atomic same-crop
   PLANT projection. When `private`, `seeds`, or a requested crop ledger is
   absent/unreadable, preserve the incumbent action.
3. Rebuild both generated standalones and prove normal technical-seed behavior
   is unchanged relative to the frozen generated controls.

## D1: static compiler

Implement canonical semantic genomes and IDs; ninth-cow lineage extraction;
money, shed, carry, seed, lifecycle, capacity, and market ledgers; independent
v27/Boatlee adapters; route/path synthesis; public entry/fallback/rejoin
contracts; attributable rejection reasons; structural roots, one-factor
mutations, deduplication, and Pareto-diversity selection.

The compiler must synthesize BUY, pickup, travel, BUILD, PLACE, and rejoin
actions from trace state. It may reject only for a concrete path, resource,
precondition, lifecycle, market-slot, actor-continuity, or rejoin defect.

## D2: exact evaluation and materialization

Reuse the audited exact-engine loader and diagnostic concepts. Evaluate fast
in-memory compiled patches against frozen lane-relative controls. Materialize
only selected candidates as self-contained research `main.py` artifacts.
Verify fast-versus-standalone equality in both seats. Use technical seed
`811407` for unchanged controls, lineage, removal/fixed8 reconstruction, and
true `-24`/`+24` compile audits.

## D3: spawn scheduler

Use Windows spawn processes and immutable canonical job manifests. Each job
writes one shard through atomic replacement; workers never append a shared
JSONL. Resume requires manifest, engine, control, compiler, candidate, and job
hash equality. Merge is deterministic and status is read-only. Failure
injection covers kill/restart, corrupt shard, engine/import failure, and worker
failure. Infrastructure failures never receive efficacy scores.

## D4: development re-audit

Run all unit/property/integration/failure tests, both builders/checks, the
shared source contract, exact fingerprint checks, serial/parallel equality,
fast/standalone parity, isolated artifact checks, latency gates, and
`git diff --check`. Write `artifacts/development_verification.json`, a command
transcript, and `development_decision.md`. Emit `READY_FOR_FORMAL_S1` only if
every required gate passes; otherwise retain evidence and emit
`DEVELOPMENT_REMEDIATION_REQUIRED`.
